SportsBeep / Beta readiness

Real-time data
beta checklist

Recommended scope: MLB, pregame single bets only. Keep live betting, parlays, and unsupported sports disabled until their data and settlement paths are verified.

ESPN can provide frequently refreshed data, but instant updates cannot be promised. Show when data was last verified and stop accepting bets when the data cannot be trusted.

Planning checklist—not a certification that these safeguards are implemented. This document does not authorize publishing or deployment.

1. Remove all fabricated data / Beta blocker

  • Delete generated matchups, random start times, random odds, and default betting lines.
  • Display “No games available” or “Odds unavailable” when ESPN has no usable data.
  • Hide unsupported sports rather than filling them with sample games.

Done when: Every displayed game and enabled selection is traceable to a real source record.

2. Make schedules and time zones accurate / Beta blocker

  • Use ESPN’s scheduled start timestamp—not the scraper’s fetch time.
  • Store timestamps in UTC; display dates and times with a clearly labeled time zone.
  • Fetch yesterday, today, and upcoming games so midnight boundaries do not lose fixtures.
  • Match updates using ESPN event IDs, including doubleheaders.
  • Update rescheduled starts and explicitly handle delayed, postponed, suspended, canceled, and final games.
  • Never assume a game is finished merely because several hours have elapsed.

Done when: Schedule checks match ESPN across midnight, daylight-saving changes, doubleheaders, and rescheduled games.

3. Add controlled refreshes and freshness tracking / Beta blocker

Initial targets are subject to ESPN’s permitted usage and observed rate limits. They are not guarantees of source updates.

DataInitial refresh target
Upcoming scheduleEvery 5 minutes
Pregame status and available oddsEvery 30–60 seconds
Games approaching startEvery 15–30 seconds, if supported
Final scores awaiting confirmationEvery 30–60 seconds
  • Track last attempted fetch and last successful fetch separately.
  • Record source update time when ESPN provides it; a fresh fetch is not necessarily a fresh bookmaker price.
  • Preserve the last good response during outages, visibly marked stale.
  • Add timeouts, retry backoff, rate-limit handling, and overlapping-request prevention.
  • Suspend wagering on data that exceeds an agreed freshness limit.

Done when: An outage cannot silently produce “fresh” games or leave stale markets open.

4. Make odds honest and complete / Beta blocker

  • Show the bookmaker/provider when supplied and the last verification time.
  • Verify home/away mapping, spread signs, totals, and American-odds conversions.
  • Leave individual unavailable markets disabled.
  • Confirm ESPN supplies enough odds coverage and update frequency for beta.
  • If coverage is insufficient, restrict beta or evaluate a dedicated odds feed—never invent prices.

Done when: Each enabled line has a known source, valid mapping, and acceptable freshness.

5. Protect bet acceptance on the server / Beta blocker

  • Look up fixtures and markets server-side instead of trusting submitted teams, starts, points, or odds.
  • Reject stale, missing, started, suspended, canceled, or closed markets.
  • Require the player to accept a new price if the price changes.
  • Save accepted price, line, source, event ID, and verification timestamp with each wager.
  • Provide an administrator switch to pause all betting immediately.

Done when: Editing a browser request or leaving a page open cannot place a bet at an invalid price.

SportsBeep / Settlement and acceptance

6. Finish results and settlement

Already covered by existing project tasks

  • Connect real final scores using the correct source event IDs.
  • Run settlement automatically and prevent duplicate payouts.
  • Define treatment for postponed, canceled, suspended, and unresolved games.
  • Keep parlays disabled until their grading is complete.

This overlaps the existing final scores, scheduled settlement, and parlays/no-result tasks. Do not create duplicate tasks.

7. Run a monitored rehearsal

Complete this before accepting real beta wagers.

  • Run through several complete MLB game days without real stakes.
  • Compare schedules, statuses, and sampled odds against their source.
  • Simulate outages, stale responses, missing markets, changed odds, and rescheduled games.
  • Verify rejected bets never debit balances.
  • Verify completed wagers settle once, with an auditable result.
  • Add an admin health view showing feed age, errors, suspended markets, and unsettled games.

Beta acceptance gate

Do not accept real beta wagers until:
  • No fabricated fixtures or odds remain.
  • Dates, times, and statuses are verified.
  • Stale markets automatically stop accepting bets.
  • Prices are validated server-side.
  • Results and payouts work end to end.
  • An administrator can pause betting immediately.

Priority order

Remove fabricated data → Fix schedules → Enforce freshness → Validate odds and bets → Complete settlement → Monitored rehearsal.
